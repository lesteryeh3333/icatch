RELEASE QUALITY PROGRAM

SDK Release 品質提升方案

針對近期發生的長時間運行穩定性問題，我們重新調整了 SDK release 的驗證流程，加強長時間可靠度測試，也把與貴司的協作方式做了些調整。

OVERVIEW

這次做了哪些調整

檢討這次事件後，我們把調整聚焦在兩個地方。

1

驗證場景對齊實際使用

把貴司實際的操作情境與長時間運行場景納入驗證，不只是我們自己原本的功能測項。

2

強化長時間可靠度測試

版本凍結前就先跑完整的長時間連續運行驗證，能提早抓到問題。

RELEASE 週期調整

Release 週期由 6 週調整為 7 週

為了把長時間可靠度驗證跟貴司測項的優先驗證都完整納入，同時讓貴司有足夠時間做整合測試，我們重新評估後決定把標準 release 週期從原先溝通的 6 週調整為 7 週。多這一週，換來的是交付前更完整的驗證，也降低交付後才發現重大問題的機會。

OUR COMMITMENT

我們的承諾

✓

版本凍結前，以貴司的測試標準先跑完整的長時間驗證

貴司拿到版本後做的是複驗跟驗收，不用再從頭去發現問題。

✓

用貴司的標準重新檢視我們現有的測試項目

比對後會據此規劃測試深度分級標準，持續補強驗證的嚴謹度。

✓

每次的問題都會變成長期的迴歸測試項目

修復後不是結案就結束，會納入之後每個版本都要跑的自動化驗證。之後如果貴司這邊還有想新增的測項，麻煩在 Week7 週一～週二提出，我們會排進下一版的規劃。

✓

正式發行前有明確的關卡

會導致當機等重大（Critical）問題沒解決，版本不會進入正式發行。

DISCUSSION

想跟貴司討論的一件事

測試資源擴充

為了支援方案裡提到的並行測試（能提高重現率、縮短驗證週期），我們想跟貴司討論看看是否能提供額外的測試機board，這樣雙方的測試效率跟驗證品質都能一起提升。
