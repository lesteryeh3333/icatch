NEW PROCESS

7 週標準流程

N 版與 N+1 版架構完全對稱，皆為 7 週。點擊項目查看細節。

N 版
  • W1
    新功能開發與除錯
    ›

    研發團隊進行本次版本規劃的新功能開發，測試團隊同步驗證。

  • W2
    Alpha 切出（週五）
    ›

    功能確認點，目的是讓 QA 測試目標穩定；之後僅接受問題修復，不再新增功能。

  • W3
    優先驗證：DMP＋新功能
    ›

    貴司測項須全數通過，與本版新功能同等優先；長時間可靠度測試同步平行進行。

  • W4
    iCatch 自身測項
    ›

    優先級較低，保留較長時間讓 side effect 與長時間測試的不確定性有機會浮現。

  • W5
    修復／Beta
    ›

    週一至四修復，週五發行 Beta，為最晚期限、非固定日期。

  • W6
    客戶整合
    ›

    貴司整合測試與 iCatch 補充驗證同步進行，問題一起處理。

  • W7
    Retest／Release
    ›

    週一二 Retest，週三四 Confirmation，週五正式發行。

N+1 版
  • W1
    新功能開發與除錯
    ›

    PM/PL 須於 N 版 W5 前提出 N+1 需求；RD 可提早於 N 版 W6、W7 開始開發（頭期優勢，非強制）。

  • W2
    Alpha 切出（週五）
    ›

    與 N 版邏輯完全相同，功能確認點。

  • W3
    優先驗證：DMP＋新功能
    ›

    長時間可靠度測試同步平行進行。

  • W4
    iCatch 自身測項
    ›

    優先級較低，保留較長時間。

  • W5
    修復／Beta
    ›

    須完成交付（deadline）。

  • W6
    客戶整合
    ›

    客戶協作驗證。

  • W7
    Retest／Release
    ›

    架構與 N 版完全對稱，不因頭期開發而壓縮 N+1 自己的週期長度。

示意圖：N 版與 N+1 版關係，兩版架構完全一致、互不壓縮彼此週期。
